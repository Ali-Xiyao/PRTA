# 效率与部署证据

> **证据角色更新**：当前数值绑定 V2-S43。最终投稿需对 Slim-S1-S43 在同一
> A800 口径重测参数量、FLOPs、batch 1/16 延迟、吞吐、显存与 state-pruning
> parity；不能把 3090 训练速度与 A800 部署表混合。

## 测量口径

- 固定硬件：单张 NVIDIA A800 80GB PCIe；
- 环境：torch 2.6.0+cu126，CUDA 12.6；
- checkpoint：冻结 V2-S43；
- batch：1 和 16；
- 20 次 warm-up，100 次 CUDA Event 重复测量；
- 范围：预加载缓存特征后的模型前向，不含磁盘 I/O、CPU→GPU 传输和原始影像
  encoder；
- 不与 RTX 3090 结果混合或平均。

## 模型与存储

| 项目 | 数值 |
|---|---:|
| Total parameters | 73,306,898 |
| Trainable parameters | 16,602,386 |
| FLOPs / sample | 74.988 GFLOPs |
| MACs / sample（2 FLOPs/MAC） | 37.494 GMACs |
| Checkpoint | 719,471,506 bytes（约 686.1 MiB） |
| 活跃缓存部署文件 | 44,252,124,061 bytes（约 41.21 GiB） |
| Cached images | 146,110 |

FLOPs 来自 `torch.utils.flop_counter.FlopCounterMode` 的已记账算子；MACs 使用
`2 FLOPs = 1 MAC` 的明确约定。论文表中必须保留此口径。

## 前向延迟、吞吐与显存

| Batch | Mean latency | p50 | p95 | Throughput | Peak allocated memory |
|---:|---:|---:|---:|---:|---:|
| 1 | 10.658 ms | 10.657 ms | 10.663 ms | 93.82 samples/s | 317.5 MB |
| 16 | 82.702 ms | 82.730 ms | 82.941 ms | 193.47 samples/s | 546.9 MB |

结果表明模型头部/尾部前向本身较轻，真正的部署存储负担来自离线 block4 特征
缓存。若部署场景不允许约 41.2 GiB 缓存，就必须另行报告原始影像 encoder 的
端到端延迟与动态缓存策略，不能把本表的 10.7 ms 直接称为“从影像到结果”的
临床延迟。

## 同一 A800 上的比较器

| 系统 | 参数量 | Trainable | GFLOPs/sample | Batch-1 mean ms | Batch-16 samples/s |
|---|---:|---:|---:|---:|---:|
| B401 Current-only | 30.138M | 1.785M | 11.712 | 1.725 | 1230.95 |
| TILA Tail8 | 62.239M | 5.534M | 47.891 | 6.928 | 303.44 |
| IF-F01 | 61.058M | 4.353M | 49.176 | 7.001 | 293.43 |
| IF-F02 | 64.013M | 7.309M | 48.943 | 7.121 | 292.88 |
| Full V2 | 73.307M | 16.602M | 74.988 | 10.658 | 193.47 |

B401 明显更快来自其 current-only 结构，不能脱离其较弱的预测性能解释。TILA8、
F01、F02 的计算量和吞吐接近；F02 参数最多，但没有形成足以替代冻结 V2 的
三 Seed 性能证据。所有数字均来自同一型号 A800 与相同 profiler。

比较器同卡测量已经补齐，因此 Table 8 可以支持相对效率描述。仍需验证 state
branch 推理裁剪前后 logits 最大差异 `≤1e-6` 且预测完全一致；raw-image encoder、
影像解码与 I/O 仍不在本表范围内。
